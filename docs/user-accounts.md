# Пользовательские аккаунты

## Функции

- `/profile/`: гостевой экран или профиль авторизованного пользователя.
- `/accounts/login/`: вход по email и паролю, безопасный возврат по `next`.
- `/accounts/register/`: email, пароль, повтор пароля, обязательное принятие политики; рассылка необязательна и выключена по умолчанию.
- `/accounts/logout/`: выход только POST с CSRF.
- `/accounts/password/reset/`: восстановление через письмо с одноразовой ссылкой Django. Неизвестный email получает ту же страницу подтверждения.
- Избранное гостя хранится в браузере. После входа переносится в аккаунт и удаляется из гостевого хранилища после успешного сохранения. Маршрут на день продолжает храниться в браузере.

Существующая `auth.User` и админский вход по username сохраняются. Новые обычные пользователи не получают `staff`/`superuser`. Email нормализуется в нижний регистр. При неоднозначном email у старых пользователей публичный вход и восстановление для него запрещены; админский вход по username работает.

В `accounts.Account` сохраняются адрес политики, дата принятия и отдельная дата согласия на рассылку. Даты согласий доступны для чтения в админке. Письма с акциями не отправляются этой доработкой.

## Настройка сервера

Добавьте в `.env.production`:

```dotenv
PRIVACY_POLICY_URL=
TEST_REGISTRATION_ENABLED=false
EMAIL_HOST=
EMAIL_PORT=587
EMAIL_HOST_USER=
EMAIL_HOST_PASSWORD=
EMAIL_USE_TLS=true
EMAIL_USE_SSL=false
DEFAULT_FROM_EMAIL=
AUTH_TRUST_PROXY_IP=true
```

`PRIVACY_POLICY_URL` — адрес утверждённой и опубликованной политики, подготовленной владельцем сервиса. При пустом адресе обычная регистрация недоступна.

`/privacy/` содержит **черновик**, доступный из профиля, подвала сайта и закрытой формы регистрации. По запросу владельца в нём указаны временное название ООО «Кидстайм» и контакт `info@kidstime.devtestenv.ru`. Компания пока не зарегистрирована: страница прямо сообщает об этом и закрыта от индексации через HTML meta и `X-Robots-Tag`. Черновик описывает текущие функции приложения, но не является утверждённой политикой.

Для тестирования по решению владельца можно включить `TEST_REGISTRATION_ENABLED=true`, оставив `PRIVACY_POLICY_URL` пустым. Тогда регистрация использует `/privacy/`, показывает пометку «Тестовая регистрация» и требует ознакомления с черновиком. Создаётся обычный аккаунт без административных прав; в записи аккаунта сохраняются адрес `/privacy/` и время ознакомления. Избранное, вход и восстановление пароля работают как обычно. Название ООО «Кидстайм» остаётся явно временным. Утверждённая политика этим режимом не создаётся.

Для завершения тестирования установите `TEST_REGISTRATION_ENABLED=false` и укажите адрес окончательной политики. Если адрес пуст, создание новых аккаунтов снова закрывается; вход в уже созданные аккаунты сохраняется. Изменения `.env.production` применяются пересозданием web-контейнера.

Для окончательной версии нужно подтвердить фактического оператора и его реквизиты, сроки и основания обработки, удаление, условия работы с внешними сервисами и почтой (включая настроенную пересылку входящих писем). Оператор определяется фактической организацией обработки, а не рабочим названием компании: [152-ФЗ, статья 3](https://mintrud.gov.ru/docs/laws/130).

SMTP нужен для восстановления пароля. Укажите разрешённый отправитель в `DEFAULT_FROM_EMAIL`. Для SMTP SSL на 465 включите `EMAIL_USE_SSL` и выключите `EMAIL_USE_TLS`. Если SMTP не настроен или отправка не удалась, форма показывает ошибку и не обещает отправку письма. Ключи и пароли не коммитить.

`AUTH_TRUST_PROXY_IP=true` подходит для существующего production Compose: web доступен только во внутренней сети за Caddy, который задаёт X-Forwarded-For. Если web доступен напрямую или заголовок может задавать клиент, оставьте false и настройте доверенный прокси отдельно.

Миграция `accounts.0001_initial` создаёт только новые таблицы. Стандартный запуск production web применяет её через `docker/entrypoint.sh`.

## Ограничение попыток

Общие для всех web-процессов счётчики находятся в базе. Пароли, открытые email и IP в них не записываются. Ключи — SHA-256 от области ограничения и временного окна. Просроченные счётчики удаляются при следующем обращении к форме.

- Вход: 20 попыток на email и 100 на IP за 15 минут.
- Регистрация/восстановление: 5 на email и 20 на IP за час.
- При превышении форма отвечает HTTP 429.

## Проверка

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py collectstatic --noinput
python manage.py test
npm run css:build
```

Ручной сценарий: сохранить событие гостем → зарегистрироваться → открыть избранное в другом браузере после входа → выйти и убедиться, что чужой аккаунт не видит подборку → запросить восстановление → сменить пароль → проверить, что повторное использование ссылки отвергается.
